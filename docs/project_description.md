# Описание проекта

## 1. Цель проекта

Построить и валидировать воспроизводимый пайплайн дообучения LLM/инструкционной модели для задач диалогового и/или инструкционного ответа на русском языке с акцентом на практическое качество, стабильность и эффективность инференса.

## 2. Задачи

1. Сформировать и задокументировать датасетный микс из открытых источников VK/Hugging Face.
2. Подготовить baseline-обучение (SFT) с фиксируемыми гиперпараметрами.
3. Реализовать набор улучшений (качество данных, LoRA/QLoRA, curriculum/data-mix tuning, регуляризация).
4. Провести серию контролируемых экспериментов с единым протоколом оценки.
5. Сравнить подходы по качеству, стоимости обучения и скорости инференса.
6. Подготовить полный комплект итоговых артефактов.

## 3. Ожидаемые результаты и метрики

### 3.1 Ожидаемые результаты

- Воспроизводимый baseline и минимум 2 улучшенных варианта модели.
- Подтверждённый прирост на целевых метриках относительно baseline.
- Документированный trade-off «качество ↔ ресурсы».

### 3.2 Метрики

**Основные (качество):**
- `Exact Match / F1` (для extractive/коротких ответов, где применимо).
- `ROUGE-L`, `BLEU` (для генеративных задач).
- `BERTScore` или аналог семантической близости.
- Win-rate в pairwise-оценке (LLM-as-a-judge/человек).

**Служебные (эффективность):**
- Throughput (tokens/s), latency p50/p95.
- VRAM/RAM usage.
- Стоимость обучения (GPU-hours).

**Надёжность:**
- Доля некорректных/токсичных ответов на safety-наборе.
- Robustness на out-of-domain подмножестве.

## 4. Открытые датасеты VK/HF: что используется и как

Ниже — рекомендуемый публичный микс (уточняется под трек и доступный бюджет):

1. **VK-related public corpora** (если релевантны треку):
   - Открытые текстовые/диалоговые наборы, опубликованные VK/сообществом VK на HF.
   - Использование: доменно-специфичный слой данных для повышения релевантности ответов.

2. **Hugging Face OpenAssistant/oasst1**
   - Использование: инструкционный диалоговый SFT-блок, очистка и фильтрация по языку/длине.

3. **Hugging Face Databricks Dolly 15k**
   - Использование: расширение разнообразия instruction-following примеров.

4. **Hugging Face UltraChat / SlimOrca (или аналогичный открытый chat-датасет)**
   - Использование: масштабирование многошаговых диалогов и reasoning-паттернов.

5. **Русскоязычные открытые наборы на HF** (например, ru-instruct/ru-dialog под совместимую лицензию)
   - Использование: приоритет русскоязычного качества и стилистической устойчивости.

### 4.1 Правила использования датасетов

- Проверка лицензий и разрешённости коммерческого/некоммерческого использования.
- Нормализация формата в единую схему: `system / user / assistant`.
- Дедупликация, language filtering, ограничение длины, удаление низкокачественных записей.
- Балансировка смеси (примерно: 40% ru-instruct, 40% multilingual/open chat, 20% domain-specific VK).

## 5. Метод обучения (baseline + улучшения)

## 5.1 Baseline

- Базовая модель: open-source instruction-tuned LLM (например, 7B–8B класс).
- Метод: SFT на очищенном датасетном миксе.
- Конфигурация: фиксированный seed, стандартный AdamW, cosine LR schedule, gradient accumulation.
- Валидация: регулярная оценка на dev-наборе по целевым метрикам.

## 5.2 Улучшения

1. **PEFT (LoRA/QLoRA):** снижение вычислительной стоимости при сопоставимом качестве.
2. **Data curriculum:** сначала короткие и чистые инструкции, затем сложные multi-turn диалоги.
3. **Loss masking и форматирование промптов:** обучение только на токенах ответа assistant.
4. **Data mix tuning:** подбор весов источников данных по результатам промежуточной валидации.
5. **Post-SFT alignment (опционально):** DPO/IPO на предпочтениях (при наличии данных).

## 6. План экспериментов

1. **E0 — Baseline SFT**
   - Зафиксировать базовую конфигурацию и метрики.
2. **E1 — LoRA/QLoRA вместо full fine-tuning**
   - Сравнить качество/стоимость.
3. **E2 — Data filtering ablation**
   - Оценить вклад очистки и дедупликации.
4. **E3 — Data mix ablation**
   - Проверить разные пропорции ru/multilingual/domain данных.
5. **E4 — Prompt/template variants**
   - Сравнить форматы чатов и системных инструкций.
6. **E5 — Final run**
   - Лучшая конфигурация + повторяемость (2–3 прогона).

Для каждого эксперимента фиксируются: commit hash, конфиг, seed, train/eval лог, итоговые метрики и затраты GPU-hours.

## 7. Формат итоговых артефактов

1. **Веса модели**
   - Чекпоинты (или LoRA-адаптеры), совместимые с выбранным рантаймом.
   - `README` с инструкцией инференса.

2. **Отчёт**
   - Подробное описание данных, обучения, результатов, ограничений и выводов.

3. **Таблицы метрик**
   - Сводная таблица baseline vs improved.
   - Отдельные таблицы по качеству, производительности и надёжности.

4. **Презентация**
   - 8–15 слайдов: цель, метод, эксперименты, ключевые графики, итог.

5. **Воспроизводимость**
   - Конфиги, версии зависимостей, команды запуска, фиксация seed и окружения.
